terraplan.

Run terraform plan on your branch without asking anyone.

Pick a repo, branch and environment. terraplan runs init and plan on a locked-down runner and shows you the diff here and on your pull request. Applies still need a DevOps approval.

Company Google accounts only.
uat · feature/rds-parameter-group




What happens when you click Run
The same steps a DevOps engineer would do by hand, minus the waiting.




You choose
Repository, branch and environment.


Lock check
If the environment is busy, you see who has it and queue.


Runner works
Clones the branch, assumes the AWS role, runs init and plan.


You read the diff
On the run page and as a comment on your pull request.


DevOps applies
An approver applies the exact plan you reviewed.




Know who has uat before you queue
Terraform state locks are invisible until your run fails. Here every environment shows the current run, its branch and the person behind it.


  • Locked by a running job
  • Waiting in the queue
  • Free to use




What developers can’t do, on purpose
Every attempt below goes through the same gate. Watch what gets through.




Run arbitrary terraform commandsOnly init, validate and plan. No state edits, no imports.
$ terraform state rm …
✕ Blockedstate commands are disabled


See AWS credentialsThe runner gets a short-lived role per environment. Nobody gets keys.
$ env | grep AWS_SECRET
✕ Blockedkeys never leave the runner


Apply without approvalDestroy and any prod apply wait for an admin. Plans never do.
$ terraplan apply --env prod
◷ Needs approvalqueued for a DevOps admin


Hide what they ranEvery run records who, which branch, which commit and which environment.
$ terraplan plan --env uat
